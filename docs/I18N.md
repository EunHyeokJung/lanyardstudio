# LanyardStudio localization

LanyardStudio keeps UI translations in `lib/i18n.ts`. The current locales are:

| Locale | Language |
| --- | --- |
| `ko` | 한국어 |
| `en` | English |
| `ja` | 日本語 |
| `zh-CN` | 简体中文 |
| `zh-TW` | 繁體中文 |
| `es` | Español |
| `fr` | Français |
| `de` | Deutsch |

## Translation behavior

- English is the source catalog and fallback locale.
- The browser locale is detected on the first visit.
- A manual selection is persisted under `lanyardstudio-locale-v1`.
- Changing the UI locale never modifies CSV headers, roster values, or canvas text.
- Landing examples, new-project rosters, and the explicit **Fill sample data** action use `SAMPLE_DATA_BY_LOCALE` in `components/BadgeStudio.tsx`.
- **Fill sample data** replaces the current roster; it is not an automatic translation of user data.
- Interpolated values use named placeholders such as `{count}` and `{name}`.

## Add or update a locale

1. Add the locale to `SUPPORTED_LOCALES`.
2. Add a `Dictionary` catalog and register it in `DICTIONARIES`.
3. Translate the high-frequency editor, data, and print keys first. Missing keys fall back to English.
4. Run `npm run check`.
5. Verify the landing page, all three workspaces, validation messages, and the install prompt at mobile and desktop widths.

Keep translations short enough for buttons and field labels. Add matching sample field names and roster values to `SAMPLE_DATA_BY_LOCALE` when adding a locale. Do not translate or overwrite existing user-controlled fields and values when switching languages.
